# AURA P1 Implementation Plan — gated preparation

> **For agentic workers:** After the entry gate is satisfied, use superpowers:executing-plans for inline execution, or superpowers:subagent-driven-development if the Product Owner selects delegation. Steps use checkbox syntax. This document does not authorize execution now.

**Goal:** Capture supported macOS application output, process it through all four existing EQ modules and play it safely to a selected output.

**Architecture:** A control coordinator owns one capture session and all HAL resources. A private process tap and owned aggregate feed a bounded real-time path through the existing EqualizerProcessor. Process/output selection, lifecycle, permission and recovery remain separate from the callback.

**Tech stack:** Swift 6, SwiftUI, public Core Audio/AudioToolbox/AVFoundation, XCTest; no new external package assumed.

**Spec:** `AURA_OUTPUT_FIRST_ROADMAP.md`, `docs/P1_ARCHITECTURE.md`; preserve `docs/MASTER_EXECUTION_PROMPT.md` P0 contracts.

## Review focus

- AURA capturing its own return must be excluded before playback (Tasks 1–3).
- A failure after muting or partial device creation must restore ordinary sound and destroy only owned resources (Tasks 1–2).
- Device loss or format changes during callbacks must not use destroyed objects or stale buffers (Tasks 2–4).
- Clock drift and queue exhaustion must produce bounded behavior and observable dropout counters (Tasks 1, 3–4).
- Permission denial, protected/silent sources and disappearing processes must be distinguished from working capture (Tasks 1–2, 4).
