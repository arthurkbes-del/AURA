# AURA P0 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. The Product Owner authorizes inline execution and ordinary implementation decisions. Steps use checkbox syntax.

**Goal:** Deliver a native menu bar app that audibly plays a local file through four independent 32-band-capable EQ stages.

**Architecture:** AVAudioEngine coordinates file playback, headroom, four serial EQ modules, master gain, and hardware output. SwiftUI observes main-actor application state; the audio controller and persistence have separate responsibilities. DSP selection is gated by real SDK and rendering evidence.

**Tech Stack:** Swift 6, SwiftUI, AVFoundation, AudioToolbox, Core Audio, Foundation, XCTest, Xcode; zero external dependencies.

**Spec:** `docs/superpowers/specs/2026-10-17-aura-p0-design.md` and `docs/MASTER_EXECUTION_PROMPT.md`.

## Global constraints

- Exactly four EQ modules; 1–32 bands per module.
- Target frequency 20 Hz to 20 kHz, gain −24 dB to +24 dB, Q 0.1 to 30; clamp to safe Nyquist bounds.
- Native Apple Silicon; Swift 6; SwiftUI; bundle identifier `com.evoluere.aura`.
- No system audio capture, driver installation, global audio routing changes, or external runtime dependencies.
- No I/O, blocking synchronization, dynamic allocation, or UI work on a real-time callback.
- No simulated measurements or unsupported PASS claims.
- Preserve unknown future data versions and unrelated work.

## Review focus

- Stale playback completion after a second file loads must not stop the new playback (Task 4).
- NaN, infinity, low sample rates, and malformed decoded arrays must never reach DSP unchecked (Tasks 2–3).
- Future-version or corrupt storage must not silently destroy user presets (Task 2).
- Device removal while playing must reach a recoverable state without unsolicited routing changes (Task 4).
- Unsupported gain/Q controls must not appear effective; Q coverage must not be silently truncated to Apple's bandwidth range (Tasks 1, 3, 5).
